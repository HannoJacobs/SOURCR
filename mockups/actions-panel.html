Discussion points from the spike

  • Data source: GitHub Actions API via gh auth (same account that already sees PPA-Wrapper). Local path → resolve origin → owner/repo. Azure remotes are out of scope unless we add ADO later.
  • What to track by default: For this repo, CD is the pain (Root Deploy Dev / Root Deploy Prod, 25–60+ min). CI finishes in ~2 min. Filters for Running / Failed matter more than a full history dump.
  • Branch rollup vs run list: Branch board (C) answers “is develop green?”; run list (A) answers “what is burning right now?”. Hybrid is natural: branch rows on the right, expand into steps like Diff.
  • Step density: Live deploy has ~90+ steps. UI should collapse to phases / current±2 steps, not dump the full GitHub job log.
  • Still read-only: Watch + open in browser. No cancel / re-run / approve from SOURCR unless you explicitly want that later.
  • Menu-bar badge: Optional later — yellow spinner / red X on the status item when any watched CD is running or failed.
